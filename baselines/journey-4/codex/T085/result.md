# PR 审查结果

发现 1 个影响用户的缺陷。

## [P1] 百分比折扣被向下取整，正常优惠订单按原价计算

位置：`samples/repo/app.py:4`，`total()` 返回表达式；对应 `change.diff` 唯一新增行中的 `discount // 100`。

触发条件：订单金额大于 0，且 `0 < discount < 100`。`//` 是向下取整除法，这一区间的 `discount // 100` 恒为 0，因此折扣系数恒为 1。整数和浮点数折扣均受影响，用户应享受的优惠被全部抹掉；若此结果用于结算，会导致多收款。

已实际调用样例源码复现：

| 调用 | 修改前公式结果 | 修改后实际结果 | 多计金额 |
|---|---:|---:|---:|
| `total(2, 100, 10)` | 180 | 200 | 20 |
| `total(2, 100, 99)` | 约 2 | 200 | 198 |
| `total(2, 100, 10.0)` | 180 | 200.0 | 20 |

复现方式：导入 `app.py` 的 `total` 并调用以上参数；原公式 `qty * price * (1 - discount / 100)` 用作修改前对照。完整机器结果见 `repro.json`。99% 案例的原公式存在浮点表示误差（2.0000000000000018），不影响该缺陷结论。

建议恢复普通除法 `/`，并覆盖普通整数百分比和浮点百分比折扣的回归用例。现有测试仅验证默认 0 折扣，实际执行虽通过，无法发现此回归；100% 折扣也仍返回 0，不能替代中间折扣值测试。本次未修改源码或测试。
