# 采购比价助手 PRD（V1 草案）

版本：0.1｜日期：2026-10-29｜状态：待业务确认

## 1. 目标与输入依据

采购人员人工上传三份报价，系统整理报价明细，计算可比较的含税到岸总价并展示差异，同时保留交期、保修对决策的影响。采购人员提出选择建议，经经理审阅以及适用的审批后导出，辅助采购决策。

已明确约束：V1 人工上传，不接 ERP，不自动下单；超过 5 万元需两级审批；预算未知。不得将价格最低直接等同于最优供应商。

本文的公式、角色划分和审批实现属于建议方案，待确认后作为开发基线；不声称业务已确定相关规则。

## 2. 用户与场景

| 角色 | 场景与需要 |
| --- | --- |
| 采购经办人 | 收到三家供应商报价，建立同一采购需求的比价单，核对型号、数量、价格口径，补齐缺项，提出选择及理由 |
| 经理（一级审阅人） | 比较金额、交期和保修，查看原始依据，接受建议或退回修改 |
| 二级审批人 | 对超过 5 万元的拟选方案进行独立审批，批准或退回 |

典型场景：最低报价的交期无法满足需求，采购人员选择交期更合适、保修更完整的方案并说明原因；金额达到条件时执行两级审批，再导出决策记录。

## 3. V1 范围

包含：建立比价单、上传并保存三份报价原件、人工录入/核对结构化数据、同口径计算、差异展示、选商建议、审阅与审批、版本留痕、导出比价报告。

不包含：ERP 集成、自动下单或付款、对外发送报价或采购通知、供应商信用评分、历史价格库、预算额度控制、自动议价。预算未知，因此本期不展示“预算内/超预算”结论。系统允许填写已知预算作为参考，但不作为审批门槛。

为降低 V1 依赖，文件上传与人工结构化录入是基础能力；自动识别报价不作为本期必需能力。建议支持 PDF、XLSX 和图片原件预览或下载，具体文件类型与大小上限需在技术评审明确；暂不承诺任意文件均可解析。

## 4. 数据与计算规则

### 4.1 比价基础

每单记录采购名称、需求物料/规格、需求数量、目的交付地点、经办人、三家供应商、比较币种、版本及拟选方案。每份报价记录原件、报价日期、有效期、物料明细、计价单位、数量、单价、金额含税状态、税率/税额、折扣、运费、保险、关税/清关及其他费用、交期、保修、费用覆盖范围。

交期保留原文，并记录起算条件（如收到预付款后）、承诺时长/日期和目的地；保修记录期限、起算点、覆盖内容、除外条款及服务方式。缺失内容标为“未提供”，不能解释为零天或无保修。

同一物料先核对规格、单位和数量。不同规格、替代品或不同数量须显式标注，记录换算依据和人工确认；不能直接把原始总价当成同口径价格。原始报价和标准化结果同时保留。

### 4.2 含税到岸总价（建议口径）

本产品暂将“到岸”定义为送达本比价单指定目的地的已知全部采购成本，业务需确认是否另指 CIF 等贸易术语。交付地点和费用承担边界未确认时，不得宣称总价完整。

`含税到岸总价 = 含税货款净额 + 未包含在货款内的含税运输费 + 保险费 + 关税/清关费 + 其他必付费用`

- 货款已含税时直接使用含税金额；未含税时按报价确认的税率计算，折扣和税的适用顺序按原报价记录。不得为未知税率套默认值。
- 每一费用记录币种、是否含税、是否已包含、金额来源；已包含费用不重复相加；零费用须明确确认。
- 含税采购支出与可抵扣进项税不混为一谈，本期不计算抵扣后的财务净成本。
- V1 基础范围为同一比较币种。不同币种先由经办人取得同币种报价；本期不提供实时汇率或自动换汇。
- 运费、税额或其他必付费用未知时，显示“已知小计 + 待确认费用”，不能将缺项置零，也不能给出最终价格排名。只有三份报价都完成可比性确认后，才显示完整总价与价差。
- 金额按币种最小货币单位逐项四舍五入后求和；人民币保留两位小数。导出与页面使用同一数据版本和公式。

差异表同时列出总价、分项费用、规格/数量差异、交期、保修、缺项与风险。价格差额以完整报价中的最低总价为基准，差额比例为 `（本方案总价 - 最低总价）/最低总价`；基准为零时不计算比例。

## 5. 用户流程与状态

1. **草稿**：经办人建立需求及交付地点，上传三份报价，填写结构化字段；支持保存未完成内容。
2. **核对与比较**：核对费用口径和可比性；系统展示缺项、差异与计算明细，允许回看原件。三份报价未齐或必需费用缺失时，可查看草稿，但不可提交审批或生成正式报告。
3. **选择方案**：经办人选择拟采购报价，填写选择理由，说明价格、交期和保修的取舍。系统不自动替用户选商。
4. **待经理审阅**：提交后冻结当前版本；经理查看三份报价、差异及建议，可通过或退回，退回须填原因。
5. **条件审批**：经理通过后，拟选方案含税到岸总价超过人民币 50,000.00 元，进入待二级审批；未超过则进入已批准。二级审批通过后进入已批准，退回则进入退回修改。
6. **导出**：已批准版本可导出 PDF 比价报告，包含三家报价明细、公式与缺项状态、交期/保修、拟选方案及理由、审批人和时间、版本号。报告不代表已下采购订单。
7. **修改**：退回后由经办人修改并重新提交。已批准内容如有报价、费用、数量、拟选供应商或交期/保修变化，生成新版本并重新审阅；旧版本保留，不覆盖旧审批记录。

## 6. 审批与权限边界

- 建议由经理审阅兼任一级审批，超过门槛再由不同的二级审批人审批，避免额外叠加三级流程；业务需确认经理是否就是一级审批人。
- 门槛按拟选方案本次采购的完整含税到岸总价判断，不按单项价格、三家报价总和或最低报价判断。50,000.00 元整不触发二级审批，50,000.01 元触发。
- “5 万元”暂按人民币解释；其他币种未确定折算与审批规则前不可完成正式审批。
- 经办人不得审批自己的比价单；两级审批人须为不同人员。审批人未配置时保留待审批状态并提示配置，不能自动视为通过。
- 经理和二级审批人可评论、通过或退回，不能直接修改报价数据；经办人负责修改。审批动作记录操作者、时间、版本和意见。
- 正式导出仅针对已批准版本；草稿可保存、查看，不提供可混淆为已审批报告的正式导出。历史报告应显式显示版本，更新后的报告标明被替代版本。
- 报价仅对经办人和被授权审阅/审批人开放；附件和导出沿用比价单权限，不能通过猜测下载链接读取他人内容。

## 7. 异常与边界

| 情况 | 行为 |
| --- | --- |
| 缺一份报价或重复上传同一报价 | 提示补齐或确认替换；不得伪造第三份；替换后保留版本信息 |
| 原件损坏、加密或无法预览 | 明确提示重新上传或人工核对可读原件；上传失败不算已齐 |
| 税率、费用含税状态或运费未知 | 标记待确认，展示已知小计，阻止最终结论与审批提交 |
| 报价过期 | 提示获取有效报价；过期报价不能作为正式审批依据 |
| 交期/保修未提供 | 显式提示风险；提交前要求经办人记录缺失情况，经理明确确认后可继续，不自动补值 |
| 审批期间修改或选商变化 | 当前审批版本不被改写，撤回后形成新版本并重新走审批 |
| 重复点击提交/审批/导出 | 不产生重复审批记录；导出记录始终关联准确版本 |
| 导出失败 | 保留已批准状态，提示重试，不显示文件已成功生成 |

## 8. 验收标准

| 编号 | 条件与可观察结果 |
| --- | --- |
| AC01 | 上传三份可读报价，保存并重开后，原件和对应结构化内容可逐一核对；不足三份不能提交 |
| AC02 | A 含税货款 45,000 元、未含入货款的含税运费 1,000 元、其他费用明确为 0；结果为 46,000 元。B 未税货款 40,000 元、报价税率 13%、含税运费 800 元，结果也为 46,000 元；公式明细可见 |
| AC03 | 运费明确已含入货款时不重复计算；运费未知时显示待确认，不能输出完整总价和最终排名或提交审批 |
| AC04 | 三份完整报价总价分别为 46,000、48,300、50,000 元，第二份相对最低价差为 2,300 元、5.00%；页面与导出一致 |
| AC05 | 不同型号、单位或采购数量被显式标记，未经人工确认可比性不能提交；原始金额仍可追溯 |
| AC06 | 差异表同时展示交期条件和保修范围；选择非最低价方案可填写交期/保修理由，导出完整保留该理由；缺失信息保持“未提供” |
| AC07 | 拟选金额 50,000.00 元经理通过后可正式导出；50,000.01 元经理通过后仍不能正式导出，待独立二级审批通过后才开放 |
| AC08 | 未授权用户不能查看附件或导出；经办人无法自批，同一人无法完成两级审批；无审批人时不能绕过 |
| AC09 | 经理或二级审批退回后，经办人能看到原因并修改重提；原版本的原件、计算结果和审批日志可回查 |
| AC10 | 已批准版本更换供应商或修改费用后，新版本重新审批；旧批准状态不能用于导出新数据，历史报告带版本标识 |
| AC11 | 导出的 PDF 包含三家报价、含税到岸金额及计算、交期、保修、选择理由与审批信息；无 ERP 调用、自动下单或付款入口 |

## 9. 待确认与交付前置

1. 确认“到岸”的实际贸易/交付定义、税费口径、是否存在跨境采购或外币需求。
2. 确认 5 万元审批口径，以及经理是否兼任一级审批、审批人配置与代办规则。
3. 确认三份报价是否始终对应三家供应商，以及不足三家是否允许例外；V1 当前不提供例外绕行。
4. 确认上传格式、单文件限制、预计单量、附件保留周期和导出模板。
5. 预算与开发资源未知，暂不承诺工期或预算校验；建议优先交付人工录入、计算、审批及导出闭环。
