# 订单系统迁移执行方案

本方案为待执行操作单，不代表已迁移或已验收。迁移窗口为周六22:00至周日02:00，业务停机累计不得超过2小时。当前仅演练100条、生产约1万条，缺少全量耗时及回退耗时证据，**目前不满足正式切换条件**。先补齐演练及核对；条件不满足时保持旧系统服务、取消本次切换。

## 1. 责任与时间边界

| 负责人 | 执行责任 | 放行责任 |
|---|---|---|
| 周宁（数据） | 生产数据盘点、原始快照与增量边界、order_id重复及冲突分析、迁前迁后核对、回退后的数据核对 | 签署数据一致性结论 |
| 张宁（实施） | 全量演练、备份恢复测试、停写与路由切换、迁移执行与日志、旧系统恢复 | 记录各步骤起止时间；发现回退条件立即停止切换并执行回退 |
| 李晓（验收） | 组织业务用例、检查停机预算、确认新旧入口和恢复服务 | 汇总周宁与张宁结论，决定放行或取消；任何数据不一致均不得放行 |

上述分工为本方案建议，窗口前由三人确认。任何一人发现回退触发项可叫停；不等待会议耗尽恢复时间。张宁执行既定回退，周宁与李晓并行核验。

采用保守安排：22:00开始在线准备；**22:30才开始业务停机，最迟周日00:30恢复可用服务**。00:30至02:00用于在线观察和核对，不得据此延长停机。停机从首次影响正常收单/处理的操作计起，直到业务入口恢复并通过收单验证；如提前影响业务，恢复截止时间也须相应提前。

## 2. 准备与放行门槛

1. **核实范围（周宁）**：取得生产实际订单数、关联表范围、状态分布、金额字段及币种口径（如存在）、有效order_id规则、更新/取消/删除方式和时区。约1万仅用于容量预估，不能作为最终核对基数。100条约为生产规模的1%，尚不能证明全量可在窗口内完成。
2. **全量演练（张宁执行、周宁核对、李晓验收）**：在隔离环境用合成或获准脱敏的生产等量/更大数据，覆盖周五新增及更新、重复order_id、冲突记录、异常记录、关联数据和故障恢复。测量全量导入、最终增量追平、核对、切换以及完整回退耗时，记录环境、数据量和资源差异。演练数据不能进入正式业务入口。
3. **确定停机预算（张宁）**：本方案暂留60分钟用于回退，最迟23:30作出放行/回退决定。此预算必须由实测支持：回退完整链路加安全余量须≤60分钟，正向最终同步、核对与验收须≤60分钟。若回退所需预留为R分钟，则最晚决策时刻为00:30减R；若前后步骤加安全余量不能压入120分钟，取消此次切换，不能靠延长窗口解决。
4. **保护旧系统与快照（张宁、周宁）**：保留可恢复的旧系统及配置。制作带时间戳、批次号、导出边界、表清单、精确行数、文件校验值的原始快照；原始文件只读保存，清洗/去重在独立副本进行。验证快照可读取、可恢复，记录存储位置和访问权限。快照保留期需窗口前确认，未批准不得删除。
5. **设计最终追平（周宁、张宁）**：旧系统周五仍收单，不能将周五导出视为最终基线；持续收集基线边界后的新增、更新、取消及删除。优先使用事务一致快照与可追踪日志位点；若系统不支持可靠增量，则必须在停写后重做一致性全量，并用演练证明能满足2小时停机。仅按创建时间过滤不够，时间戳水位必须有重叠补采和order_id幂等处理，以免漏掉晚提交或更新。
6. **准备回退与防双写（张宁）**：核实域名/路由、连接配置、任务队列、定时任务、接口写入方及第三方回调；具备统一停写和恢复手段。新系统切换验证阶段仅允许受控验收，正式业务写入须等全部签字后开启。预先验证迁后新增/更新回补旧系统的方式和耗时；没有可靠回补能力时，不得开放新系统正式写入。
7. **窗口前签字（李晓）**：以上证据、操作人到场、通讯方式、回退操作单及核对基准齐备才进入窗口。预装/预导入可以在线完成，但不得影响旧系统正常收单，也不得让新系统提前处理正式订单。

以下时间为拟定安排，以演练验证后的更早决策点为准。

| 时间 | 操作与责任人 | 必须留下的证据/退出条件 |
|---|---|---|
| 周六22:00—22:30 | 张宁检查环境、旧系统健康、路由恢复能力和备份；周宁核对批次、增量可用性；李晓确认放行条件 | 任一前置条件缺失，直接取消，旧系统继续收单 |
| 22:30 | 张宁关闭全部业务写入口，暂停消费者、定时任务和写入回调，处理或登记在途请求；周宁确认最后提交位点 | 记录停机起点、实际恢复截止时间；证明无残留写入，无新旧双写 |
| 22:30—23:10（目标） | 周宁生成最终一致性快照/尾部增量，保留原始件；张宁按批次幂等装载，迁移关联数据 | 源端冻结位点、批次与日志可追溯；失败批次可重跑但不重复造单；一旦威胁回退预算立即回退 |
| 23:10—23:30（目标） | 周宁完成全量数据核对；张宁在受控入口验证配置；李晓验收核心业务路径 | 核对差异为零或每项有明确业务解释和三方批准；丢单、冲突及错金额不能豁免 |
| 最迟23:30 | 李晓汇总签字，张宁按结果开放新系统或执行旧系统回退 | 未完成、未签字、证据不完整一律回退。实测R>60分钟时必须更早决策 |
| 放行后—00:30 | 张宁切换唯一正式入口并确认队列与任务仅一侧运行；李晓验证真实业务链路；周宁持续核对切换后的变更 | 记录恢复时刻和停机分钟数；关键故障立即按回退流程处理 |
| 00:30—02:00 | 三人在线观察订单流转、错误与积压，复核切换后的数据 | 保持旧系统及快照可用，形成交接与异常清单；02:00结束迁移值守前确认后续负责人 |

## 4. 数据核对与验收口径

周宁在冻结后的源端生成最终清单，张宁导出目标清单，李晓复核结论。不得只抽样100条或只看总数。

- **唯一性和重复**：以order_id识别同一订单；分别统计原始行数、非空order_id数、唯一order_id数、重复组数和重复行数。空ID或无法解释的同ID内容冲突阻断迁移。完全相同重复可按批准规则折叠；同ID不同版本必须结合源系统权威版本/事务顺序确定，不能任意保留首条。保存去重映射、保留记录和排除原因，原始快照不改动。
- **集合完整性**：以批准处理后的唯一order_id集合为基准，计算“源有目标无”“目标有源无”，均须为0。原始记录数=保留记录数+已登记排除记录数；目标订单数=源端应迁唯一订单数。不得把合法去重导致的行数下降误报为丢单，也不得用总数相等掩盖丢单与多单相抵。
- **字段一致性**：按order_id全量对比实际存在的业务关键字段，如客户/商品关联、金额、币种、数量、状态、创建/更新时间。使用约定的空值、时间及时区规范；金额按原精度或最小货币单位比较，按币种分组，不混币求和。对无须变换的字段采用规范化摘要核对，对转换字段留转换规则及逐项差异报告。
- **汇总与关联**：逐状态/日期/币种的订单数与金额合计一致；检查关联主键存在性、明细数及孤立记录。每批记录输入、成功、失败、跳过和去重数量，失败/未解释跳过必须为0；最终增量到冻结位点已全部应用。
- **业务验收**：李晓覆盖历史订单查询、关键状态显示、关联详情、一次受控新建和后续更新，以及重复order_id重试不重复建单。按系统实际支持的核心路径执行，不假定有支付/库存等未说明功能。验收订单须标记且进入核对台账，所有外部副作用受控。
- **服务验收**：张宁确认正式入口指向唯一可写系统、任务无双跑、接口无持续错误及异常积压，核心链路响应符合窗口前确认的旧系统基线/服务要求。没有既定性能阈值时须在演练后明确，不能临场凭感觉放行。

每项记录批次号、冻结位点、源值、目标值、差值、结论、证据路径、执行人和时间。任何差异需定位到具体order_id；修正后重跑受影响项及总量/集合核对。

## 5. 回退触发与操作

以下任一项触发立即回退或在停机前取消：原始快照不可恢复；冻结后仍有未受控写入；增量范围无法证明完整；丢单/多单、关键字段错误、无法解释的order_id冲突；导入失败或关联断裂；核心收单/查询/更新验收失败；新旧双写/任务双跑；持续关键错误或性能超过已批准阈值；达到最晚决策时刻仍无三方签字；预测剩余工作将侵占恢复预算。

1. **停止新端（张宁）**：停止新系统写入口及任务，阻断外部重复执行，保存故障日志、批次和最终目标快照。记录故障时刻及最后写入位点，不删除新端数据。
2. **确认回退数据（周宁）**：如新系统尚未开放正式写入，旧系统冻结数据就是业务基准；受控验收记录单独登记。如已正式写入，先导出切换后全部新增/更新/取消/删除，用order_id及版本顺序幂等回补旧系统，处理冲突并核对关联数据和副作用，不能直接丢弃新端订单。
3. **恢复旧端（张宁）**：优先解除完整旧系统的写保护，恢复原路由、连接、任务及回调；仅旧数据损坏时使用已验证的原始快照恢复并补齐已确认增量。确保任务仅在旧端运行。
4. **核验并开放（周宁、李晓）**：完成回补集合/字段/金额核对，李晓验证旧端查询、收单、更新和幂等；张宁确认入口及队列正常后恢复服务，记录停机结束，须在实际停机起点+120分钟前完成。
5. **收尾（三人）**：保留两侧数据、原始快照、回补清单与故障证据，说明影响订单及处理状态，安排原因修复和重新全量演练；本窗口不盲目再次切换。

若实际故障已导致无法在2小时内安全恢复，张宁立即升级为故障处置，李晓记录超时与业务影响，周宁保护在途数据。不得为满足时限而跳过回补或声称已经恢复。该情形说明停机目标未达成，需如实报告。

## 6. 待确认项与最终交接

正式执行前仍需取得：具体周末日期、实际数据量及表结构、全部写入口清单、增量机制、全量及回退演练结果、快照保存位置与保留期、性能阈值和异常升级联系人。它们不影响编制方案，但会阻止生产切换放行。

交接包包含：原始快照清单与校验值、迁移/去重/回补规则、逐批执行日志、全量差异报告、业务验收记录、三方签字、实际停机时长与最终服务系统、未解决异常及责任人。本次仅交付方案，不包含生产迁移、实际数据核验或业务签字。
