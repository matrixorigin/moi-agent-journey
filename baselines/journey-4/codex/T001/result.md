# 青岚制造访谈需求提炼

来源：`samples/shared/interview.md`，访谈日期 2026-10-20。以下“未满足需求”为依据原话归纳的产品需求，不代表受访者已确认具体实现方案。

## 目标

| 项目 | 提炼 | 原话依据 |
|---|---|---|
| 提高报价整理效率 | 减少每周三家报价复制、整理的人工作业时间。 | 林岚：“我每周收三家报价，复制到Excel要两小时。” |
| 做出有依据的采购选择 | 先了解比较依据，由采购人员决定供应商。 | 采购经理：“我想先看到比较依据，再决定选谁。” |
| 验证试点价值 | 先在一个采购组试点，月底用每单耗时衡量效果。 | 主管：“希望先试点一个采购组，月底看每单耗时。” |

## 当前做法与约束

| 项目 | 提炼 | 原话依据 |
|---|---|---|
| 报价整理 | 每周接收三家供应商报价，人工复制到 Excel，耗时两小时。 | 林岚：“我每周收三家报价，复制到Excel要两小时。” |
| 审批规则 | 超过 5 万元的采购需要两级审批；原文未说明恰好 5 万元的规则。 | 周宁：“超过5万元需要两级审批。” |
| 报价保密 | 供应商报价不得发到公开群。 | 周宁：“我们不能把供应商报价发到公开群。” |
| 登录与留存 | 系统仅允许公司账号登录，报价至少保留一年。 | 陈航：“系统只允许公司账号登录，报价至少保留一年。” |
| 集成现状 | 尚无现成 ERP 接口。 | 陈航：“我们没有现成ERP接口。” |
| 推进条件 | 预算尚未批准，当前只表达了小范围试点意愿。 | 主管：“希望先试点一个采购组……预算还未批准。” |

## 痛点

| 项目 | 提炼 | 原话依据 |
|---|---|---|
| 重复录入耗时 | 将报价复制到 Excel 每周耗费两小时。 | 林岚：“复制到Excel要两小时。” |
| 运费遗漏导致误判 | 单看报价可能选错，计入运费后价格高低会反转。 | 林岚：“最怕运费漏算。上次便宜的报价加运费反而贵了。” |

保密、账号、审批和留存属于明确约束；访谈未证明这些方面已经发生事故。预算未批准是推进限制，不能据此认定已获采购承诺。

## 未满足需求

| 项目 | 需求提炼 | 原话依据 |
|---|---|---|
| 减少报价搬运 | 提供便捷的报价录入、导入或整理能力，减少人工复制；具体输入格式待确认。 | 林岚：“我每周收三家报价，复制到Excel要两小时。” |
| 完整成本比较 | 将运费纳入比较，清楚展示各报价的成本构成与比较依据，避免遗漏。 | 林岚：“最怕运费漏算。上次便宜的报价加运费反而贵了。”；采购经理：“我想先看到比较依据。” |
| 人工决策边界 | 比较后由采购人员选供应商，不自动替用户下单。 | 采购经理：“再决定选谁。不要替我直接下单。” |
| 审批支持 | 对超过 5 万元的采购支持两级审批要求；审批角色和金额口径待确认。 | 周宁：“超过5万元需要两级审批。” |
| 安全访问和分享 | 限公司账号访问，避免供应商报价流向公开群；具体授权范围待确认。 | 周宁：“我们不能把供应商报价发到公开群。”；陈航：“系统只允许公司账号登录。” |
| 报价留存 | 报价可保存至少一年。 | 陈航：“报价至少保留一年。” |
| 无 ERP 接口下可试用 | 试点方案应可在没有现成 ERP 接口的条件下运行；访谈未指定替代集成方式。 | 陈航：“我们没有现成ERP接口。” |
| 试点与效果衡量 | 支持一个采购组试点，并记录每单耗时供月底评估；对照基线与目标值待确认。 | 主管：“希望先试点一个采购组，月底看每单耗时。预算还未批准。” |

## 后续待澄清

- 报价文件格式、运费规则及是否还有税费等成本项，访谈未说明。
- 审批金额按含运费总额还是其他口径计算，两级审批人及恰好 5 万元的处理待确认。
- 公司账号认证方式、报价可见人员、留存起点与一年后的处置方式待确认。
- 每单耗时的起止点、当前基线、试点目标及预算批准条件待确认。每周复制报价“两小时”不能直接当作“每单耗时”基线。
