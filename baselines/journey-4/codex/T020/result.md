# 是否上线自动下单：决策正反论证

**建议：暂不开放生产环境无人审批的自动下单；有条件开展受控试点。** 当前材料支持验证价值，但尚不能证明价格完整、订单正确写入和错误订单可撤回。试点先采用影子运行和人工确认，实际下单仍由获授权人员完成。经理愿意试点不等于已批准生产自动下单。

## 支持上线的证据及边界

| 已知证据 | 支持理由 | 尚不能据此断言的事项 |
|---|---|---|
| 每单节约20分钟 | 重复下单操作有明确提效空间 | 未说明测量方法、样本和是否扣除复核、异常处理时间，不能视为净收益 |
| 经理愿意试点 | 有业务推动者，可组织验证和反馈 | 不代表采购权限、预算和风险责任均已落实 |
| 上月100单 | 有历史订单可用于回放和建立人工基线 | 只有一个月样本，代表性与订单复杂程度未知 |
| 试点预算3万元，2人可投入两周 | 具备有界验证的资源窗口 | 尚无成本拆分，也未证明两周内可完成ERP联调及控制措施 |

以过去100单为参考：若每单均适用且确实净节约20分钟，潜在节约为100×20÷60＝**33.3小时**。这只是该订单量下的理论上限，不能直接换算为已实现收入或年度收益。2人×两周＝4人周的投入容量；预算是否覆盖人力及接口费用待确认。

## 反对直接上线的证据及影响

| 已知证据 | 反对理由 | 应如何验证或处理 |
|---|---|---|
| 报价缺运费占18% | 可能按不完整总价选错供应商，或出现预算偏差 | 先明确18%的分母、期间及缺失原因；运费未补齐时阻断自动下单 |
| ERP接口未打通 | 无法证明订单能完整、正确写入ERP；可能漏单、重复下单或状态不一致 | 在测试环境完成端到端写入、回读核对、超时重试与幂等验证 |
| 撤单规则未知 | 错误订单产生后，撤回窗口、费用和责任均不明确 | 按供应商及订单状态确认撤单条件，并验证可执行的处置流程 |
| 上月100单中12单被人工改选 | 历史人工干预率为12%，表明原选项存在需要复核的情况 | 逐单标注改选原因，判断是价格、交付、质量、偏好还是规则缺失 |

12%不能直接解释为算法错误率，也不能假设这12单均可由规则自动解决。报价缺运费的18%与改选的12%分母未确认一致、重叠未知，**不能相加为30%的问题订单率**，也不能推算剩余70单都适合自动下单。

## 决策前需补充的信息

1. **业务范围与收益**：哪些订单可自动化；20分钟是估算还是实测；各类订单量、复核耗时、异常处理耗时和人力成本。由业务负责人给出基线，计算净节时和收益。
2. **总价与改选原因**：18%的统计口径、完整到岸/交付成本字段；12笔改选的逐单原因及与运费缺失的交集。由采购与数据负责人核对，形成明确的排除与审批规则。
3. **ERP可用性**：接口责任人、接入工期、权限和测试环境；订单唯一标识、重试机制、失败告警及双方对账方式。由技术负责人提供端到端测试证据。
4. **撤单与责任**：下单何时形成承诺，谁可撤单，窗口、费用及失败后的升级路径；自动化可操作的金额、品类与供应商范围。由业务负责人确认，必要时请合同负责人核实。
5. **资源与验收**：3万元覆盖项目、供应商费用和人力的方式；两人的职责、两周期限内的可交付范围；试点负责人、审批人、停止权限和后续运维安排。

## 分阶段决策条件（以下为建议，需业务负责人确认）

| 决策 | 放行条件 | 未满足时的处理 |
|---|---|---|
| 开始受控试点 | 明确负责人、样本、范围及预算；可使用脱敏历史订单或测试环境；保留人工确认；两周内先完成100单回放及12笔改选原因核查（数据可取得时） | 数据或环境未就绪则只做准备与澄清，不承诺生产下单 |
| 开始小范围生产自动下单 | 运费等必要总价字段完整，否则阻断；ERP写入、回读、幂等、异常告警与对账验证完成；撤单和补救流程可执行；采购授权、单笔/累计限额、供应商白名单及人工接管已确认 | 任一关键控制缺失则维持人工审批 |
| 扩大上线 | 在事先约定的订单类型、样本量和观察期内，净节时为正且达到约定目标；成本在3万元预算内；无重复单、漏单、未授权下单或无法追溯订单；所有差异均完成解释与闭环 | 样本不足则继续有限验证；出现关键事故则暂停自动下单并人工接管 |

不把“试点零事故”视为长期风险已清零。上线前需书面约定净节时目标、允许的人工介入率、覆盖范围及观察期，避免看完结果再改验收标准。**两周是资源窗口，不是强制上线日期。** 到期按证据决定扩大、继续验证或停止；预算或时间不足时优先收缩范围，保留ERP一致性与撤单控制。
