# 自定义业务 Skill：J2-111 连续会话

一个 case 使用 `matrixorigin/moi_ai_native_skills` 的真实「进度管理」包，完整执行：上传 ZIP 预检/导入 → 创建绑定该 Skill 的候选 → 确认发布 → 回读发布配置与绑定 → 同一会话连续追问 → 独立核对数据与交付 → 统一清理。

Skill、智能体和会话各创建一次，10 个阶段共 19 轮用户消息。创建使用页面对应的候选/确认后端 API，不覆盖浏览器点击，也不要求 Momo 通过自然语言生成创建候选。新智能体收到的业务请求不提示 Skill 名、ID、脚本名或命令。

此复杂用例总限时 900 秒，单轮最多 300 秒；限时包括设置及业务执行，清理另有有限时间并单独计时。其他 Journey-2 用例仍为 300 秒。套件并发 3，此 case 内的追问严格串行。

| 阶段 | 轮数 | 连续业务与验收重点 |
|---|---:|---|
| initialize | 1 | 同意初始化空业务库；真实 init/reference_data；三张业务表为空；员工仅有九个必需列，编号前导零保留 |
| customer | 2 | 新建客户预览、下一轮确认；主表与分支变化正确；捕获实际创建的客户 ID |
| progress | 2 | 给刚才客户新增历史逾期事项，按姓名关联三类负责人；确认后捕获实际事项 ID |
| update | 2 | 同一事项替换备注、清空产品负责人；确认后其他字段保持、版本递增 |
| cancel | 2 | 另一客户新增预览后取消；主表不变，变更 canceled，分支移除 |
| select | 2 | 两个新客户独立预览；原始勾选清单送入下一轮，只提交选中项，另一项 pending |
| block | 2 | 原事项从待开始改为阻塞；确认后保存原因与 resume_status |
| resume | 3 | 请求非法直接完成并验证拒绝、无写入；再预览和确认恢复原阶段 |
| report | 1 | 未结束逾期事项按销售负责人汇总；实际查询并交付可下载 CSV，核对 ID、姓名、数量 |
| refresh | 2 | 查询原事项；测试更新自己的员工来源；再次查询实时关联新姓名，原编号不变 |

## 固定输入与工作流配置

上游版本固定为 `38718c1ccc0f2bf5010f50de854342a8cf217c44`，包路径 `business_process_management/dist/business-progress-management.zip`。SHA-256 和七个成员名保存在根目录 `native-skills.json`。

上游仓库是私有仓库，源文件不提交到本公开仓库。原始 ZIP 作为 journey-2 的固定 QA 输入上传；GitHub 的 `qa` environment variable `MOI_J2_NATIVE_SKILL_SOURCE_FILE_ID` 指定该文件。执行时使用已有 QA PAT 下载，严格核对包 SHA-256、成员清单和大小。缺变量报告 blocked；错包直接报错，不切换来源。

为允许并发，每次只把 SKILL.md frontmatter 的名称改为唯一测试名，正文、引用、SQL 和脚本字节不改。上传后逐文件下载校验，并记录原包/成员 SHA-256。固定源 ZIP 是可复用输入，清理不删除它。

测试只准备含三名合成员工的只读来源和空业务库，并在智能体配置中持久绑定。业务表、客户、事项全部由智能体创建；后续追问复用这些实际数据，不在阶段间重新建库或重置数据。汇总场景只有一条逾期事项，主要验证查询与 CSV 交付，不覆盖多状态过滤组合。这里测试已配置数据源的运行链路，不覆盖自然语言创建阶段执行 check_employees、自动生成并持久化业务库名称、跨会话恢复或长时间缓存过期。

## 判定与证据

核验智能体在该会话中自行读取真实绑定 Skill、下载文件；需要脚本的轮次核验 bash 执行 `progress.py` 对应命令、退出码及 JSON 结果（完整查询对象或实际行投影均按字段值核验）。已读取的 Skill、员工目录和已确认的业务状态可在会话中复用，不强制重复读取；非法状态拒绝可以依据此前已核验状态。随后由测试通过 SQL API 独立回读主表、变更表和分支表，不把最终回复中的「成功」当作数据库证据。

预览要求主表和既有变更不动，只出现预期 pending 变更及分支；确认要求选中项生效、未选中项不动；取消要求主表不动。只有独立 SQL 核验通过、且已出现在用户可见回复中的真实 change_id 才送入后续确认。客户/事项 ID 从核验后的预览记录中捕获，不提前伪造。

前置数据未成立时，同阶段后续轮次及依赖阶段标为 dependency_blocked，不发送追问，也不制造多个衍生失败；例如新增事项失败后仍可测试独立的客户取消和选择确认。数据库已正确变更但回复格式不合格时，保留本阶段失败，后续数据操作可继续。超时或执行中断则停止发送，报告区分当前失败、依赖阻塞和未执行。DATETIME 的 SQL/脚本表示仅统一 UTC 后缀和日期格式，保留微秒。

每个阶段和每轮分别记录 pass/fail/blocked/dependency_blocked/not_run；Markdown 报告显示阶段结果、已验收轮次、耗时、依赖阻塞原因和各轮 trace。完整 JSON 保留失败检查项。报告保留 trace/task/session、各轮回复、工具参数/输出、SQL 前后快照、实际交付文件、判定及清理记录。QA 若把脚本工具输出截为摘要，无法核实退出码/结果时明确报告 blocked（证据不完整），不从截断预览猜测成功。自然语言路径受模型影响；固定数据和确定性验收不意味着智能体每次必然通过。失败照常出报告，符合现有功能结果与框架结果分离规则。

## 清理

先停止未结束的任务并完整取证，再：

1. 在原会话执行单独的有界清理任务，删除本 case 唯一临时目录并通过工具输出验证不存在；清理任务独立记录，不混入业务任务耗时或工具指标。
2. 删除本会话/本任务/本智能体的成果引用和无引用的底层文件，核对删除结果。
3. 用创建时保存的 ID、名称和目录身份核对本 case 的业务库、员工库；确认无外部引用后删除整库，包含待确认分支表，并核对列表不再返回。
4. 归档本次创建的智能体，解除绑定，删除导入的自定义 Skill；会话归档保留产品审计历史。

清理失败记录为 harness error，并保留待清理资源身份；不会把未确认清理写成完成。所有数据库删除仅作用于本次创建且名称预先不存在的数据库，不删除工作区已有数据。
