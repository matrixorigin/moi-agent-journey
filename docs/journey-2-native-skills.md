# 自定义业务 Skill：J2-111～J2-120

这 10 条使用 `matrixorigin/moi_ai_native_skills` 的真实「进度管理」包。每条完整执行：上传 ZIP 预检/导入 → 创建绑定该 Skill 的候选 → 确认发布 → 回读发布配置与绑定 → 与新智能体对话 → 独立核对数据与交付 → 清理。

创建使用页面对应的候选/确认后端 API，不覆盖浏览器点击，也不要求 Momo 通过自然语言生成创建候选。新智能体只收到业务请求，提示中没有 Skill 名、ID、脚本名或命令。每条独立 Agent、Skill、会话、员工库和业务库；默认 300 秒任务时限，套件并发 3。清理另有有限时间，并单独计时。

| Case | 场景 | 验收重点 |
|---|---|---|

| J2-112 | 新建客户，预览后下一轮确认 | 预览不改主表；真实 change_id；确认后新记录入主表、分支移除 |

| J2-120 | 员工姓名改变后再次查询事项 | 测试只修改自建员工表；第二轮实时关联新姓名，保留原员工编号 |

## 固定输入与工作流配置

上游版本固定为 `38718c1ccc0f2bf5010f50de854342a8cf217c44`，包路径 `business_process_management/dist/business-progress-management.zip`。SHA-256 和七个成员名保存在根目录 `native-skills.json`。

上游仓库是私有仓库，源文件不提交到本公开仓库。原始 ZIP 作为 journey-2 的固定 QA 输入上传；GitHub 的 `qa` environment variable `MOI_J2_NATIVE_SKILL_SOURCE_FILE_ID` 指定该文件。执行时使用已有 QA PAT 下载，严格核对包 SHA-256、成员清单和大小。缺变量报告 blocked；错包直接报错，不切换来源。

为允许并发，每次只把 SKILL.md frontmatter 的名称改为唯一测试名，正文、引用、SQL 和脚本字节不改。上传后逐文件下载校验，并记录原包/成员 SHA-256。固定源 ZIP 是可复用输入，清理不删除它。

员工库由测试准备并实际回读，业务库在创建配置中持久绑定。J2-111 留空业务库供智能体初始化；其余使用固定 schema 和少量合成数据。这里测试已配置数据源的运行链路，不覆盖自然语言创建阶段执行 check_employees、自动生成并持久化业务库名称、跨会话恢复或长时间缓存过期。

## 判定与证据

每轮同时检查真实 `skill` 调用、下载绑定文件、bash 工具执行 `progress.py` 对应命令、退出码及 JSON 结果（完整查询对象或实际行投影均按字段值核验）。随后由测试通过 SQL API 独立回读主表、变更表和分支表，不把最终回复中的「成功」当作数据库证据。

预览要求主表和既有变更不动，只出现预期 pending 变更及分支；确认要求选中项生效、未选中项不动；取消要求主表不动。只有核验通过的真实 change_id 才送入后续用户确认，预览失败不会猜 ID 或强行继续。DATETIME 的 SQL/脚本表示仅统一 UTC 后缀和日期格式，保留微秒。

报告保留 trace/task/session、各轮回复、工具参数/输出、SQL 前后快照、实际交付文件、判定及清理记录。QA 若把脚本工具输出截为摘要，无法核实退出码/结果时明确报告 blocked（证据不完整），不从截断预览猜测成功。自然语言路径受模型影响；固定数据和确定性验收不意味着智能体每次必然通过。失败照常出报告，符合现有功能结果与框架结果分离规则。

## 清理

先停止未结束的任务并完整取证，再：

1. 在原会话执行单独的有界清理任务，删除本 case 唯一临时目录并通过工具输出验证不存在；清理任务独立记录，不混入业务任务耗时或工具指标。
2. 删除本会话/本任务/本智能体的成果引用和无引用的底层文件，核对删除结果。
3. 用创建时保存的 ID、名称和目录身份核对本 case 的业务库、员工库；确认无外部引用后删除整库，包含待确认分支表，并核对列表不再返回。
4. 归档本次创建的智能体，解除绑定，删除导入的自定义 Skill；会话归档保留产品审计历史。

清理失败记录为 harness error，并保留待清理资源身份；不会把未确认清理写成完成。所有数据库删除仅作用于本次创建且名称预先不存在的数据库，不删除工作区已有数据。
