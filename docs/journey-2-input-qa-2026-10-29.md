## 两条失败

J2-80 的 `message.metadata.files = {"invalid": true}` 返回 HTTP 500；J2-81 的 `semantic_model_ids = [-1]` 和 `semantic_model_ids = {"invalid": true}` 也返回 HTTP 500。补充正文取证后，两条仍失败，正文均为 JSON-RPC `-32603`、`reason=INTERNAL`。验收要求输入错误被明确拒绝（HTTP 400 或 `-32602`），因此保留 fail；没有把任意失败响应算作参数校验通过。

三次错误请求前后的实际任务列表相同，没有创建任务；同会话后续合法追问能回答原有代号。说明这次发现的是错误输入的错误分类/反馈缺陷，不是已观察到任务继续执行或上下文丢失。具体后端根因仍需结合日志定位。

| J2-80 非数组附件元数据 | `c1e0bb6cce633c4e8fb1c10a03a5a441` |

## 用例与清理约束

- J2-79 的无效角色和缺失 messageId 分别验证；J2-80 的缺少 URI 分支通过，非数组元数据分支失败。
- J2-82 先建立本次合成知识库并携带选择对话，确认任务结束后删除自己的知识库；旧选择明确被拒绝，移除选择后正常追问。最终清理不会再次删除已确认删除的对象。
- J2-83/J2-84 第二轮只有 file part，没有空文本占位符；CSV/图片来自仓库固定校验和的合成材料，上一轮只提出处理要求，不提供答案。
- J2-85 对缺失必填 conversation_id 和非法模式分别发起一次手动候选请求，之后正常发布并实际对话。意外返回的候选只有核对本次 agent ID 后才纳入清理；结果未知时停止并报框架错误。
- J2-86 检查非法工具 kind/side_effect_class，核对没有创建对象，再正常创建、发布绑定并真实调用 HTTP 工具。类型和副作用枚举来自目标版本 [AgentTool 校验](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/pkg/model/agent_tool_metadata.go)。
- 所有正常任务仍保存流、持久化事件、工具调用和最终任务；只有确认任务终结后才清理本次资源。框架成功时 case job 为绿色，功能失败继续显示在报告中。
