## 失败现象

### J2-123：禁用 Tool 后基本信息编辑被拒绝

先真实调用本次 Tool，随后将其设为 disabled。PATCH 智能体名称及描述返回 HTTP 400。case 保留这一失败，继续验证独立的修复操作：同一请求移除失效 Tool 并加入本次健康 Tool，回读绑定和随后真实调用均通过。不会因为替换成功而把编辑失败改成通过。

准备资源、首轮调用、变更后的定义与 HTTP 交互均保留在证据中。本轮只新增 disabled 状态下的编辑/替换；其他状态的运行隔离路径由 J2-113～J2-118 覆盖。对应 [#19944](https://github.com/matrixorigin/matrixflow/issues/19944)。

### J2-124：只修改提示词仍累积包内自定义 Skill

创建含一个自定义 Skill 的 Agent 包，通过 current-agent 的 `base_revision` 发起两次仅修改 `agent_md` 的修订并确认。相同逻辑 Skill 的未归档目录记录从 1 条增加到 2 条、3 条，元数据分别指向 1.0.0、1.1.0、1.2.0。两个“不累积重复安装记录”断言均失败；当前包内绑定仍只有一个有效 Skill，最终实际调用及内容断言通过。

验收不要求各版本使用同一资源 ID；检查的是目录中未归档的重复安装记录。系统附带、非包内的 Skill 不计入包内绑定数量。清理前保留两次资源快照，Agent 归档后删除本次包派生的全部 Skill；删除前逐个核对 workspace、agent_id 和包内逻辑名称。对应 [#20082](https://github.com/matrixorigin/matrixflow/issues/20082)。

### J2-126：下一轮任务完成，却回答了上一轮内容

同一会话内依次发送：正常代号复述、使用请求级不存在模型发送“只回复 HELLO”、恢复正常模型请求复述新的指令内容。中间任务真实进入 failed，记录 Astra `server_error` / `RUNTIME_GATEWAY_FAILED`；不是普通工具报错或取消。下一轮创建了新的 completed 任务，但最终答复为 `HELLO`，没有包含当前请求要求的代号，因此 case 为 fail。

## 成功路径和验收边界

- J2-125 使用本次候选和禁止覆盖的包元数据触发发布拒绝，检查没有半成品 Agent；修订新候选后正常确认并实际对话。它覆盖公开 API 的可控发布失败恢复，不模拟注册器断线或其他内部故障。关联 [#19807](https://github.com/matrixorigin/matrixflow/issues/19807)、[#18918](https://github.com/matrixorigin/matrixflow/issues/18918)。
- J2-127 同步发出两次确认；至少一次成功，另一次可成功指向同一版本或返回 409，任何 500 均不通过。确认后只有一个 runnable/default 版本；已完成候选再次提交按现有契约返回 409，版本链不变，实际对话成功。
- J2-128 通过真实成果 resolve 得到 volume_id/file_id，使用与页面一致的 volume_files 选择加入新建知识库，没有把下载文件重新上传。等待来源解析成功后，在独立会话选择该知识库，检查检索、来源引用和 PDF 预览字节。关联 [#19507](https://github.com/matrixorigin/matrixflow/issues/19507)。

J2-126 的中间 failed 是明确的预期步骤，只有任务、trace、错误类型符合预期且后续完成新指令才可通过；其他 case 的失败不会因此被忽略。case job 颜色仍代表框架和取证完成，功能结果单独报告。
