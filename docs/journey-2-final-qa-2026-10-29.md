## 五条功能失败

- **J2-80/J2-81/J2-89：错误输入返回 HTTP 500。** 分别是非数组附件元数据、负数/非数组知识库选择、不存在的附件引用及 ID/URI 不一致。错误正文为 JSON-RPC `-32603` / `INTERNAL`，不符合明确的输入错误拒绝。请求前后任务列表相同，没有意外创建任务；后续合法追问和附件读取成功。这里只确认现象，后端根因需结合对应日志定位。
- **J2-91：HTTP 工具未拒绝 schema 外参数。** 本次工具的 `input_schema` 禁止额外属性，但真实调用 `{"unexpected": 1}` 仍执行成功并返回 HTTP 200；合法参数后续调用成功。验收要求错误参数被明确拒绝，所以仍为 fail。
- **J2-102：任务列表分页 total 不一致。** 当前会话有 2 个实际任务，前两页 `total=2`，末尾空页变成 `total=0`。会话分页、置顶筛选以及用户/智能体历史分页均通过。

## 测试修订与首次结果

开发期发现并修正以下测试条件或验收器问题，原始记录保留在各 batch 下：

- J2-88 首次执行时 case 尚未生成，准备阶段失败，没有进入 QA；生成材料后才开始真实测试。
- J2-101 不能假设 Momo 绑定所有内置 Skill；改为给本次智能体显式绑定 20 个非外部 Skill，再逐个实际加载。该测试只验证可绑定/可加载，不等于 20 类业务场景全部覆盖。
- J2-98 默认版本字段实际位于 `lineage.default_version`；J2-99 同版本内容冲突的公开契约是 HTTP 400。按目标版本源码校正，未放宽到任意成功/失败。
- J2-89 合成 CSV 的计算应使用 `quantity * unit_price`，没有 `amount` 列；修正请求后仍复现附件输入返回 500。
- J2-90 首轮命令末尾追加 echo 将上传失败的退出码掩盖为 0；请求改为直接执行上传命令。验收仍要求真实非零退出和 413/大小限制错误，不接受仅复述失败。32 MiB 是运行时成果发布上限，不能当作普通目录文件上传的上限。
- J2-102 初始标题可能被自动生成标题替换；分页前明确重命名本次三个会话，再按独有前缀筛选。修正后仍复现任务 total 缺陷。
- J2-87/J2-88 在答复断言之外增加真实下载、解码尝试和解码器错误的 task/call 关联；防止模型只说“不可读”便通过。加强后两条均通过。
- J2-98 统一运行时业务验收通过，但导出 ZIP 存在文本记录目录，发布步骤发生 UTF-8 解码错误。修正为既有二进制 `outputs/package/` 目录，递归扫描规则保持不变；补测真实 QA 及 ZIP 发布/内嵌凭据拒绝后通过。旧发布失败及原始导出包仍保留。
