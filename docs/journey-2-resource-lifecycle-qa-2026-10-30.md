## 断言覆盖

- J2-113～J2-118：创建并发布真实智能体，绑定目标资源与另一健康资源；先成功调用目标，再将其改为 disabled/archived/draft。在已有会话和新会话验证普通回复、健康资源调用、失效资源不能成功执行，重新启用后再次实际调用。不能仅凭模型说“调用成功”通过，需匹配 task、工具、call 和结果事件。
- J2-119/J2-120：两个智能体共享一个资源。一方归档后，另一方分别为 active/draft/disabled 时仍需阻止删除（422 + TOOL_IN_USE/SKILL_IN_USE），拒绝不能改动资源。两方都归档后，允许修改描述、禁用、启用及删除；归档智能体的历史绑定必须保留。
- J2-121/J2-122：依赖禁用时恢复智能体被拒绝且归档状态不变；启用依赖后恢复并实际对话；再归档、删除依赖后，恢复再次被拒绝且历史不变。

MOI 页面中的删除智能体使用归档语义，依据[现有产品回归](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/tests/menu_agent_square_test.go)及[引用保护](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/pkg/service/agentresource/binding_reference.go)。绑定中的资源直接删除本就受保护，因此不伪造“活跃智能体保留已删除资源”的状态。

## 发现的问题与定位

Tool 变为 disabled、archived 或 draft 后，下一轮只要求普通回复及调用另一健康工具，仍返回 JSON-RPC `-32603`，domain=`moi-core.agent_runtime`、reason=`INTERNAL`。这发生在任务受理阶段，**没有新的 task ID**，不能归为工具调用失败，也不能借用上一轮 task trace 表示这次失败。

| Case | 失败请求的会话 ID | 失败请求 Trace ID |
|---|---|---|
| J2-113 | `cd33085c-0f57-4194-9e96-21a8a2307f9d` | `3308cb9f8028d86c45d2a40eb822f6f0` |
| J2-114 | `cebfbd18-2f25-4f16-93ac-5f799205c906` | `88d8e69df0504fd6e54c40f28d7f6156` |

该现象在两个完整的三状态批次中均复现。它与 [Tool 运行时准备代码](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/pkg/service/agentresource/automation_tool_runtime.go)拒绝非 active 绑定的路径一致；本次没有查询服务器日志，内部根因仍应根据上述请求 trace 核对。相同设计下三种 Skill 状态全部通过。

新增 `admission-rejections/` 证据：只有收到明确的运行时拒绝，且完整任务列表、归属、终态及会话空闲事实一致，才确认没有新任务并清理。网络断开或响应丢失不能仅凭列表暂时为空判定可清理。原始错误、请求 trace、会话、逐轮公开事件和工具参数均保留。
