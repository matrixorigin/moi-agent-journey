# Journey-2 智能体功能覆盖清单

目标是逐项覆盖发布版本的智能体基本功能。**case 数量和通过率都不是功能覆盖率**：一条 case 可以覆盖多个步骤，也可能只覆盖某个功能的一种用法。下表中的 case 表示已实现的检查，不表示它在 QA 中一定通过；空项和“待补”仍需实现和实际验证。

范围延续当前约定：智能体及其工具、文件、知识库和第三方单向调用链；保留候选卡片与知识库选择的前端路径。插件、双向通信、跨会话持久记忆暂不纳入。自动化、工作流、团队、模型配置、身份和权限自身，以及其他页面视觉和浏览器兼容性暂不作为本组目标。

知识库在 Journey-2 只验证智能体使用知识库的基本功能：选择、简单问答和引用等。复杂检索质量、长程场景和性能留待后续专门的 Journey；单次问答通过不代表检索性能达标。

清单依据 QA MOI `5cbc08857938` 的 [会话与任务测试](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/tests/menu_agent_chat_test.go)、[智能体创建与资源测试](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/tests/menu_agent_square_test.go)、[工具与插件测试](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/tests/menu_agent_tools_test.go) 、[Skill 生命周期测试](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/tests/menu_agent_skills_test.go) 及 [QA 可选资源快照](journey-2-inventory-2026-10-28.md) 整理。产品版本和启用项可能变化；合入新功能时需同步更新清单，不能把当前清单当作已冻结的全部功能。

## 完成标准

- 根据目标发布版本的实际能力及配置逐项核对本表，为每条路径关联可运行的 case；对适用的失败和边界也要有可核对的预期，不能只测试成功路径。
- 测试先确定请求、材料和验收条件。QA 不通过时保留 case 和原始证据；只有发现测试条件或验收本身有事实错误时才修订，并保留原因和前后结果。
- 每个功能 case 分别报告 `pass`、`fail`、`blocked` 或 `error`；阻塞、执行错误和漏跑都不能算通过。Case job 颜色表示测试和证据框架状态，不代表功能通过。
- 核对目标版本、部署一致性与前置资源；当前只记录 QA MOI 后端构建，尚未完整核验 Astra、模型服务及功能开关版本。功能清单和这些条件完成前，Journey-2 不能作为发布门禁。

模型调用有随机性，即使断言是确定的也不能根据单次运行认定稳定；不静默重试或把后来成功覆盖先前失败。报告保留每轮 task/trace、事件和工具错误，供复核。
