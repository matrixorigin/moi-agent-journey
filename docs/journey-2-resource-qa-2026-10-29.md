## 保留的错误与测试修订

- J2-72 刻意请求不存在的 HTTP 资源，真实返回 404，之后在同一会话调用另一个工具成功。报告列出工具、参数、HTTP 状态、正文和 task/call ID，将该次 404 标为预期测试错误，仍计入实际工具失败数。HTTP provider 的调用封装成功不等于目标请求成功。
- J2-78 最终导入和使用成功，但模型先按 Skill 显示名称调用失败，再发现并改用资源 ID 成功。首个 `TOOL_EXECUTION_FAILED / Agent Binding skill not found` 保留为非预期错误，不能据此宣称先前 J2-65 的问题已修复。
- 工具首轮功能断言均通过，但清理请求将全部工具引用置空，触发内置 Skill 的工具依赖保护（409）。清理改为仅对本次资源发送精确 remove 操作；新运行和旧对象的补充清理均确认完成。首轮错误和单独清理记录保留。
- J2-77 首轮错误地要求归档后成果仍可见。QA 的 [成果 DAO](https://github.com/matrixorigin/matrixflow/blob/5cbc08857938/moi/pkg/dao/tenant/agent_runtime_artifact.go) 明确使归档会话的成果退出读取范围。验收改为：历史和任务保留，归档时成果列表和详情不可用，恢复会话后同一成果重新出现，并重新从 QA 下载比较字节；不使用本地缓存充当下载成功。原始失败记录保留。

HTTP 工具只 GET 本公开仓库固定提交 `caf0dbe7c549b71fa09e3eb3d201adf10059aa92` 的合成 case 文件及一个随机不存在路径；不需要第三方凭据或新增服务。创建、修改、绑定与真实调用分别验收；仅元数据操作成功不能算工具可用。
