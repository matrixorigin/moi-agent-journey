## 失败与不确定性

- **J2-114：数据修改正确，确认后的交付格式不符合 Skill。** 主表备注完整替换、产品负责人置空、版本递增、其他字段保持，均通过独立 SQL 核验；最终“变更确认”部分只有 ID，没有保留上游明确要求的完整 `确认 <change_id>`。不是数据库未提交。
- **J2-116/J2-117：bash 工具返回真实内部错误。** 业务预览未生成，因此不猜 ID、不发送后续确认。结束时的清理命令也遇到 JSON-RPC `-32000`，原始报告记为 error。随后仅补做原会话清理并核验完成，保留原始失败判词；没有重跑业务来替换失败。
- **J2-118：同类 bash 内部错误，未读取真实事项状态。** 虽然智能体解释了状态规则、数据库未改变，但不能据此证明非法状态转换功能正确，保留 fail。
- **J2-120：QA 返回截断后的工具结果，证据不足。** 两轮回复给出了前导零正确的员工编号及更新后的姓名；但刷新轮脚本输出是 `astra.external_tool_result_summary.v1` 摘要，不能独立核实完整执行结果，报告 blocked，而非声称功能失败或成功。

“sandbox: unbound”出现在智能体解释和运行时元数据里；根因尚未定位。这里能确认的是对应 bash 调用返回 `TOOL_EXECUTION_FAILED` / `stream_transport` / JSON-RPC `-32000`。没有修改共享 QA 或产品代码。
